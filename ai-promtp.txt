## 2. PHYSICAL INTERLOCKING & JOINERY MATHEMATICS (ZERO-GLUE PRECISION)

Every model in PuzzleCore is a REAL physical object cut from flat sheets (plywood, acrylic, or MDF) that snaps together with friction-fit mortise-and-tenon joinery without glue.

### A. The Parametric Mortise Slot Rule (`cutouts`)
All slots receptive to material thickness MUST be parametric using `(t || 3.0) + (clr || 0.10)`:
```javascript
// HORIZONTAL SLOT (thickness along Y, slot length along X):
{ x: slotCenterX, y: slotCenterY, w: 20, h: (t || 3.0) + (clr || 0.10) }

// VERTICAL SLOT (thickness along X, slot length along Y):
{ x: slotCenterX, y: slotCenterY, w: (t || 3.0) + (clr || 0.10), h: 30 }
```
- `t`: Material thickness in millimeters (passed into `generate2D`, typically `3.0`).
- `clr`: Kerf & friction-fit clearance tolerance (passed into `generate2D`, typically `0.10`).
- **NEVER hardcode slot thickness to `3` or `3.0`!** Hardcoding causes physical validator errors when users change sheet thickness to 2mm or 4mm.
- **Center-Based Local Coordinates**: In `cutouts`, `x` and `y` represent the **CENTER** of the cutout rectangle, NOT the top-left corner.
- **Joinery Slots vs Decorative Openings**: The physical auditor evaluates all `cutouts`. To prevent joint looseness warnings, decorative features (doors, windows, surface patterns) should be drawn in `engravings` or given proper joint dimensions.

### B. The Matching Tenon Tab Rule (`outline` extension)
Every tab that inserts into a mortise slot must match the slot's dimensions exactly:
1. **Tab Width**: Must equal the receiving slot's length:
   $$\text{Tab Width} = \text{Slot Length}$$
   *(Example: If slot length is 30mm, the protruding tab along the mating edge must be exactly 30mm wide).*
2. **Tab Protrusion Depth**: Must equal material thickness $t$ (or $t + 0.2\text{mm}$ for positive flush fit):
   $$\text{Tab Depth} = t$$
   *(Example tab extending downward along bottom edge $y = -25$ from $x = -15$ to $+15$:)*
   `outline: [ [-25, -25], [-15, -25], [-15, -25 - t], [15, -25 - t], [15, -25], [25, -25], [25, 25], [-25, 25] ]`
3. **Safety Edge Margin**: Never place a mortise slot closer than $5\text{mm}$ to the outer edge of any part. Slots cut too close to the boundary will snap during physical assembly.

## 3. ZERO-COLLISION & OVERLAP PREVENTION (RIGID SOLID BODIES)

In real physical manufacturing, two laser-cut sheets cannot occupy the same volume.

1. **NO PENETRATING SOLID BODIES**:
   - Parts may ONLY touch where tenon tabs penetrate mortise slots, or face-to-face.
   - Solid plates must NEVER intersect or cross each other without a corresponding slot cut into one or both parts!
2. **CORNER & T-JOINT THICKNESS OFFSETS**:
   - When two perpendicular walls meet at a $90^\circ$ corner, one wall must be inset or shortened by thickness $t$, or they must use alternating box/finger joints.
   - When a vertical wall rests on a horizontal base plate at $Y = 0$:
     - Base plate thickness spans from $Y = -t/2$ to $Y = +t/2$.
     - The solid body of the vertical wall must sit at $Y \ge +t/2$ (wall base at $Y = +t/2$).
     - Only the protruding tenon tabs should penetrate down into the base plate ($Y = -t/2$ to $+t/2$).
3. **SYMMETRIC BOUNDING BOX CENTERING**:
   - The platform centers each 2D shape at local $(0, 0, 0)$ when extruding 3D geometry.
   - Design your 2D outlines symmetric around local $(0, 0)$ (e.g. `[-width/2, -height/2]` to `[width/2, height/2]`) so local coordinates predict 3D world alignment accurately.

## 4. 3D POSITIONING & EULER ROTATION ALIGNMENT

Parts are positioned in 3D world space using:
- `assembledPos: [x, y, z]` (in millimeters)
- `assembledRot: [rx, ry, rz]` (in radians, Three.js Euler order 'XYZ')

### Standard Orientation Cheat-Sheet:
| Orientation | `assembledRot` | 2D Local $(X, Y)$ Maps To 3D World |
| :--- | :--- | :--- |
| **Horizontal Baseplate** (Flat on floor) | `[-Math.PI / 2, 0, 0]` | Local $X \to \text{World } X$, Local $Y \to \text{World } -Z$, Thickness $\to \text{World } Y$ |
| **Front / Back Wall** (Facing Z) | `[0, 0, 0]` or `[0, Math.PI, 0]` | Local $X \to \text{World } X$, Local $Y \to \text{World } Y$, Thickness $\to \text{World } Z$ |
| **Left Wall** (Facing -X) | `[0, Math.PI / 2, 0]` | Local $X \to \text{World } Z$, Local $Y \to \text{World } Y$, Thickness $\to \text{World } -X$ |
| **Right Wall** (Facing +X) | `[0, -Math.PI / 2, 0]` | Local $X \to \text{World } -Z$, Local $Y \to \text{World } Y$, Thickness $\to \text{World } X$ |
| **Horizontal Roof / Top Plate** | `[-Math.PI / 2, 0, 0]` | Local $X \to \text{World } X$, Local $Y \to \text{World } -Z$, Thickness $\to \text{World } Y$ |

## 5. ASSEMBLY SEQUENCE & REACHABILITY RULES

1. **Step 0**: Always the full assembly (`num: 0, title: 'Full Model Assembly'`).
2. **Step 1**: The foundation / baseplate / core spine (`parts: ['BASE-01']`).
3. **Step 2 to N**: Progressive installation of uprights, cross-members, walls, and roof.
4. **REACHABILITY CONSTRAINT**:
   Every part in `step: K` ($K > 1$) MUST include in its `connections` array at least one `partId` from an earlier step ($< K$).
   *Example: If Part W-01 is in Step 2, its connections must include `'BASE-01'` from Step 1.*
5. **VALID PART IDs ONLY**: Every ID in `connections: [...]` and `assemblySteps[].parts` must exist in `parts: [...]`. No phantom or misspelled IDs!

The project is done only when:

2. Every part has an identity.
3. Every required connection is defined.
4. Connectors physically match.
5. Material thickness is respected.
6. Tolerances are respected.
7. Parts do not have invalid collisions.
8. The assembly has a valid construction sequence.
9. The parts are physically manufacturable.
10. The 2D cutting geometry is correct.
11. The pieces can be arranged on manufacturing sheets.
12. The 3D model accurately represents the physical result.
13. Assembly instructions can be generated.
14. A child can understand how to assemble it.
15. The final physical object is stable and recognizable.

## 3. Part Schema & 2D Geometry Engine

Every piece in `parts: [...]` represents a real physical laser-cut part:

```javascript
{
  id: 'CH-01',                         // Unique Part ID (engraved on piece)
  fileName: 'CH-01_baseplate.svg',     // Standalone physical SVG filename
  name: 'Chassis Baseplate',           // Human-readable part name
  category: 'Foundation',              // Foundation | Structural | Roof | Details | Support
  color: '#8c6239',                    // 3D Preview HEX Color (wood, painted tones)
  step: 1,                             // Assembly sequence step (1 to N)
  width: 120,                          // Bounding width in mm
  length: 80,                          // Bounding length in mm
  sheet: 1,                            // Which manufacturing sheet it is nested on (1, 2, ...)
  fileSizeKB: '1.4 KB',

  // --- 3D POSITION & ORIENTATION ---
  assembledPos: [0, 0, 0],             // Final 3D position [X, Y, Z] in millimeters
  assembledRot: [-Math.PI / 2, 0, 0],  // Final 3D rotation [Euler radians: X, Y, Z]
  explodeVec: [0, -40, 0],             // Displacement vector [X, Y, Z] when exploded

  // --- PHYSICAL CONNECTIONS ---
  connections: ['CH-02', 'CH-03'],     // IDs of parts that physically interlock with this part

  // --- PARAMETRIC 2D CUT CONTOUR GENERATOR ---
  /**
   * Generates the 2D cutting and engraving profile.
   * @param {number} t - Material thickness (2.0, 3.0, or 4.0 mm)
   * @param {number} kerf - Laser kerf compensation (typically 0.15 mm)
   * @param {number} clr - Slot clearance tolerance (typically 0.10 mm)
   */
  generate2D: (t, kerf, clr) => ({
    // 1. OUTER CUT OUTLINE (Red Laser Line): Closed 2D polygon [X, Y]
    // The part's local origin [0, 0] should be near the centroid.
    outline: [
      [-60, -40], [60, -40], [60, 40], [-60, 40]
    ],

    // 2. INTERNAL MORTISES / SLOTS (Red Laser Cutouts):
    // For slots receptive to thickness 't', slot width MUST equal (t + clr) or (t + 0.10).
    cutouts: [
      // Rectangular slot:
      { x: 0, y: -30, w: 30, h: t + clr },
      // Vertical slot:
      { x: -50, y: 0, w: t + clr, h: 25 },
      // Arched gothic window / door cutout:
      { x: 0, y: 0, w: 16, h: 28, arched: true }
    ],

    // 3. VECTOR SURFACE ENGRAVINGS (Sky Blue Laser Lines):
    engravings: [
      { type: 'line', x1: -40, y1: 0, x2: 40, y2: 0 },
      { type: 'rect', x: -20, y: -10, w: 40, h: 20 },
      { type: 'circle', x: 0, y: 0, r: 8 },
      { type: 'cross', x: 0, y: 15, size: 10 }
    ]
  })
}
```

## 4. Universal Physical Connector Rules (Zero-Glue)

To pass the built-in **Physical Feasibility Auditor** ([`validation.html`](file:///d:/downloads/2-3D%20Basic/validation.html)), follow these rules:

1. **Mortise Slot Width**:
   $$\text{Slot Width} = t + \text{clr} \quad (\text{typically } t + 0.10\,\text{mm})$$
   *Never hardcode slot thickness to a constant number like `3.0`.* Always use `t + clr` or `t + 0.10` so when the user selects $2\text{mm}$, $3\text{mm}$, or $4\text{mm}$, the slot resizes automatically.

2. **Tab Dimensions**:
   A tab protruding from an edge should extend by:
   $$\text{Tab Depth} = t \quad (\text{or } t + 0.2\,\text{mm})$$
   $$\text{Tab Width} = \text{Matching Slot Length}$$

3. **Step Reachability**:
   - Every part in Step $N$ ($N > 1$) must list at least one mating connection to a part from an earlier step ($< N$).
   - A roof or exterior panel cannot be added in Step 1 if the foundation is not yet placed.

4. **Explode Direction**:
   - Baseplates explode downward (`[0, -40, 0]`).
   - Roofs explode upward/outward (`[0, 50, 0]`).
   - Left walls explode negative-X or negative-Z (`[-50, 0, 0]`).
   - Right walls explode positive-X or positive-Z (`[50, 0, 0]`).
